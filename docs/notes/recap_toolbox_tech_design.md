# RECAP 技术方案：让 VLA 在"四工具精确入槽"任务上自我提升

> **读者**：会用 Python、了解深度学习基础，但没做过 VLA / 机器人策略训练。
> **任务**：机器人把四个工具（螺丝刀、扳手、钳子、锤子）依次抓起，精确放进工具箱上对应的四个凹槽。
> **目标**：读完知道 RECAP 是什么、为什么这么设计、以及要动手做的每一步具体干什么、产物是什么、什么算合格。
>
> 本文与任何具体仿真器无关。文中的"参考经验值"来自我们在另一个精密插放任务
> （试管入架，双臂 14 自由度、三路相机、25fps）上跑通的一轮，用来给你一个量级感，不是硬指标。

---

## 第 0 章 一句话总结

普通做法是**只拿成功的示教数据做模仿学习**，模型学到的上限就是示教者的平均水平，失败数据全部扔掉。

RECAP 做的是：

1. 让当前策略自己去做任务，录下一堆轨迹（大部分是失败的）；
2. 训练一个**价值函数**，它看一帧画面就能打分"从这里出发，这个任务还有多大希望、还要多久"；
3. 用价值函数算出每一帧的**优势（advantage）**——"这一步比平均水平好还是差"；
4. 把"好/差"这个二值标签**当成一句话拼进模型的语言指令里**（`Advantage: positive` / `Advantage: negative`），
   照常做模仿学习；
5. **部署时永远说 `Advantage: positive`**，模型就只输出它学到的"好"那一类动作。

于是失败的轨迹不再是废料：一条失败轨迹里"前三个工具放对了、第四个掉了"，前面做对的那些帧照样会被
标成 positive 进入训练集。这是 RECAP 相比纯模仿学习最大的收益来源，尤其适合你这种**多阶段、
整体成功率很低但局部经常做对**的任务。

## 第 1 章 前置概念（VLA 小白必读）

### 1.1 VLA 是什么

VLA = Vision-Language-Action model，视觉-语言-动作模型。它是一个大模型，每一步：

```
输入： 若干路相机图像（比如 头部相机 + 左腕相机 + 右腕相机）
     + 机器人本体状态（关节角/夹爪开度，比如 14 维）
     + 一句自然语言指令（"Put the four tools into their slots in the toolbox."）
输出： 未来一小段时间的动作序列（action chunk，比如未来 50 步 × 14 维关节目标）
```

它的骨架通常是一个视觉-语言模型（VLM，比如 PaliGemma / Gemma）加一个动作头。之所以叫
"Vision-Language-Action"，是因为语言指令是**真正的模型输入**——改一个字，输出的动作就会变。
**RECAP 正是利用这一点**：往指令里塞一个 `Advantage: positive` 的小标签，就能在不改任何网络结构、
不改部署代码的前提下，给模型加一个"我要好的行为"的开关。

### 1.2 现在的主流训法：模仿学习（SFT / 行为克隆）

采集人类遥操作的示教数据（专家数据），每一帧构成一个 `(观测, 指令) → 动作` 的监督样本，
最小化预测动作与示教动作的差距。简单、稳定、有效，但有三个天花板：

| 问题 | 表现在你的任务上 |
|---|---|
| **只会模仿平均行为** | 示教者有时从左边插、有时从右边插，模型学成一个"平均姿态"，反而两边都对不准 |
| **失败/次优数据无法利用** | 采到的 100 条轨迹里 90 条是失败的，全扔掉；标注成本白花 |
| **不会自我提升** | 模型跑一万次也不会变好，因为没有任何反馈告诉它哪次做得好 |
| **误差累积（compounding error）** | 第一个工具插歪了 2mm，机器人进入了示教数据里从没出现过的状态，之后动作彻底崩掉 |

### 1.3 为什么不直接上强化学习

理论上 RL 正好解决这些问题。实际上在 VLA 上非常难：

- **要在线交互**：PPO 这类算法要一边训一边和真机/仿真交互，一个 7B 模型跑一次推理几百毫秒，
  真机采一条轨迹一分钟，样本效率根本不够；
- **奖励难定义**：精密插入的稠密奖励极难手工设计，稀疏奖励（成功=1）在 4 阶段任务上几乎学不动；
- **算法不兼容**：现代 VLA 的动作头多用 flow matching / diffusion，拿不到动作的 `log π(a|s)`，
  PPO 的重要性采样比值算不出来，得改算法；
- **训练不稳**：大模型 + RL 的联合训练很容易崩，而 VLA 训一次动辄几十小时。

### 1.4 RECAP 的取巧之处

RECAP（来自 π\*0.6 的方法，全称可理解为 "RL with Experience & Corrections via Advantage Conditioning"）
的核心工程判断是：**不要做在线 RL，把 RL 拆成三个各自独立、各自稳定的监督学习问题**：

| RL 里的东西 | RECAP 怎么替代 |
|---|---|
| 环境奖励 | 一集结束时的**成败标签**（成功/失败），加上"还剩多少步" |
| 值函数估计（critic） | 一个**独立训练的价值模型**，普通监督回归，训完就冻结 |
| 策略梯度更新 | **把 advantage 二值化写进 prompt，做普通的模仿学习** |

三步全是离线的、可断点重来的、可单独验收的。这就是它能在大 VLA 上落地的原因。

## 第 2 章 三个部件的原理

### 2.1 部件一：成败标签

每一条轨迹（一集 / episode）需要一个二值标签：`success` 或 `failure`。

- **专家示教数据**：天然全部标 `success`（前提是数据已经清洗过，见 §5.4）。
- **策略 rollout 数据**：需要判定。三种来源，按可靠性排序：
  1. **脚本判定**：如果你的场景里能拿到工具和凹槽的位姿（真机上用视觉定位/标记点，仿真里直接读），
     写一个判定函数：四个工具的位置都落在对应槽位公差内、姿态直立、并且**连续稳定 N 帧**。
  2. **视觉分类器**：拿一个小模型看最后一帧（或几个视角的最后一帧）判成败。需要先标几百张图。
  3. **人工复核**：人看视频打标。最慢但最准。

  **实践建议：脚本判定打初标 + 人工复核全部"成功"的那些**。原因是脚本判定的典型失效模式是
  "判定触发的那一刻是成功的，但之后工具又滑出来了"——我们在试管任务上就撞到过这个（150 集里
  评估器判成功 11 条，人工看视频后有 1 条其实是失败）。假阳性标签对价值函数的毒性远大于假阴性。

- **强烈建议额外记录"完成件数 0~4"**。二值标签是 RECAP 的必需项，但件数分布是你后面做所有
  决策（要不要拆子任务、有没有进步）的关键依据。这一列不参与训练，只用于分析。

标签的存储：**用一个独立的边车文件**（如数据集根目录下 `episode_success.json`：
`[{"episode_index": 0, "success": true, "n_placed": 4, "seed": 12345}, ...]`），
不要只写在数据集元数据里。因为数据格式转换工具几乎都会丢掉非标准字段，边车文件是跨轮次
唯一可靠的标签载体。**这一条是血泪教训**：上一轮的数据当专家数据复用时如果边车丢了，
所有失败集会被整体当成 success，价值函数直接训废。

### 2.2 部件二：价值函数 V(s)

#### 它是什么

一个独立的小模型，输入一帧观测（图像 + 本体状态 + 任务指令），输出一个 [-1, 0] 的实数：
**越接近 0 表示"这个状态很好，马上就能成功"，越接近 -1 表示"要么还早得很，要么已经没救了"。**

#### 训练目标怎么定义

对第 `i` 集的第 `t` 帧：

```
剩余步数 remaining = 集长度 L_i − t − 1
c_fail  = 该任务里最长一集的长度 × 1.0        （失败惩罚，量纲与步数一致）

原始回报 g = −remaining                        （成功集）
          = −remaining − c_fail                （失败集）

归一化   V*(t) = clip( g / (L_max + c_fail),  −1,  0 )
```

直觉解读：

- 一集**成功**的轨迹，最后一帧 `V* = 0`（马上就成功了），越往前越负（还要花时间）；
- 一集**失败**的轨迹，即使是最后一帧也被压到 `−c_fail/(L_max+c_fail) ≈ −0.5` 以下；
- 于是这个值同时编码了两件事：**"这条路走得通吗"** 和 **"还要多久"**。

这就是为什么数据池里**必须同时有成功和失败的 rollout**。如果全是成功的，模型只学到"还剩多久"，
学不到"能不能成"；如果全是失败的（你的任务初期很可能如此），模型会把所有状态都打成 -1，
advantage 全是噪声。**专家数据在这里的作用就是提供成功样本的锚点。**

#### 模型结构（参考实现）

不需要很大，0.7B 量级就够：

```
图像（每路相机） → SigLIP 视觉编码器（siglip-so400m-patch14-384）→ 池化特征
指令文本 + 离散化的本体状态 → Gemma-3-270m → 文本特征
       ↓                              ↓
    线性投影 512                   线性投影 512
       └────────── concat 1024 ──────────┘
                     ↓
              LayerNorm → MLP → 201 维 logits
```

注意最后一层是 **201 个 bin 的分类头**，不是回归到一个标量。把 [-1, 0] 均分成 201 个刻度，
真实目标值用 two-hot 编码（落在相邻两个 bin 上按距离分配权重），损失是交叉熵。
这叫**分布式价值学习（distributional value head）**，比 MSE 回归稳定得多——回归容易被
异常值拖着塌成均值，分类头能表达"我不确定，可能好也可能坏"。

预测值 = softmax(logits) 与 bin 中心的加权和。

本体状态是**离散化后拼进文本 prompt** 的（比如每维量化成 256 档写成 token），
不走单独的编码器分支，实现简单且效果够用。

参考超参：全量微调（视觉和语言塔都不冻结），lr 5e-5，warmup 500 步，cosine 衰减到 1e-6，
batch 64（约 27.5GB 显存），约 5.4 秒/步。

### 2.3 部件三：优势条件化（ACP，Advantage-Conditioned Policy）

价值函数只告诉你"状态好不好"，还差最后一步：把它变成策略能吃的训练信号。

#### 第一步：从 V 反推每一帧的稠密奖励

```
r_t = V*(t) − V*(t+1)        （同一集内的相邻帧）
r_T = V*(T)                  （集的最后一帧）
```

这是从训练目标本身差分出来的，不需要你手工设计奖励函数。

#### 第二步：n-step advantage

```
A_t = Σ_{k=0}^{n−1} r_{t+k}  +  V(t+n)  −  V(t)          n = 50，γ = 1
```

（如果 `t+n` 超出这一集，bootstrap 项取 0。）

含义："接下来 50 步实际拿到的回报 + 50 步后模型估的价值" 减去 "模型现在估的价值"。
**大于 0 = 这 50 步走得比模型预期的好**，小于 0 = 比预期差。

`n=50` 在 25fps 下是 2 秒——大致是"一次对准 + 一次下插"的时间尺度。**如果你的控制频率或
单个动作时长不同，要按比例调整**：让 n 覆盖一个有意义的动作单元，太短只能看到抖动，
太长会把好坏动作混在一起平均掉。

#### 第三步：二值化

在**同一个任务内、把所有帧（专家的和 rollout 的）混在一起**算分位数：

```
阈值 = quantile(所有 A_t, 0.7)
indicator_t = 1 if A_t >= 阈值 else 0        # 即 top-30% 记为 positive
```

这里有个新人一定会困惑的现象，先说清楚：**专家数据的帧最后只有大约 10% 被标成 positive，
这是正常的、正确的。** 因为专家动作对价值函数来说高度可预测，V 估得很准，
所以 `A ≈ 0`；而 rollout 里那些"从糟糕状态里突然救回来"的帧，A 会显著为正。
**advantage 衡量的是"比预期好多少"，不是"绝对好不好"。** 不要试图人为把专家帧全部强制为正，
那会退化回普通模仿学习。

#### 第四步：拼进 prompt 训练

```python
# 训练时
if 有 indicator:
    if random() < 0.3:            # 30% dropout：也学"没有标签"的条件
        prompt = base_prompt
    else:
        tag = "Advantage: positive" if indicator == 1 else "Advantage: negative"
        prompt = f"{base_prompt}\n{tag}"

# 推理/部署时：请求里没有 indicator 这个字段
prompt = f"{base_prompt}\nAdvantage: positive"     # 永远挂 positive
```

30% dropout 的作用是让模型在没有标签时也能正常工作（保留基础能力，也防止过度依赖标签）。

#### 为什么这样就能变强（直觉）

模型学的是条件分布 `π(a | s, 指令, 好/坏)`。训练时它见过大量"这种状态下的好动作"和
"这种状态下的坏动作"，被迫学会**区分**二者；部署时你把条件固定在"好"这一档，
它就只在好的那一半分布里采样。

这和 Decision Transformer 的"条件在目标回报上"、RLHF 里"条件在偏好上"是同一个套路，
本质是**用条件建模代替策略梯度**：不用算梯度上的 RL，只用监督学习就拿到了策略改进。
代价是你必须有一个靠谱的价值函数来提供"好/坏"标签——所以第 6 步的质检是整条链路里最关键的一环。

## 第 4 章 每一步具体做什么（针对"四工具入盒"）

下面每一步给出：**做什么 / 输入 / 输出 / 怎么判断这一步过关 / 常见翻车**。

---

### Step 0：任务与数据规格定义

**做什么**：把任务的边界钉死。这一步花半天，能省后面一周。

| 项目 | 需要定下来的东西 | 对"四工具入盒"的建议 |
|---|---|---|
| 指令文本 | 一句固定的英文指令，**训练和评估必须逐字一致** | `Put the four tools into their slots in the toolbox.` |
| 观测 | 几路相机、分辨率、本体状态维度 | 头部 + 双腕三路 480×640；状态 14 维（双臂 6+1） |
| 控制频率 | fps，直接决定 n_step 怎么取 | 25 fps（则 n_step=50 ≈ 2 秒） |
| 单集上限 | 超过就判失败，决定 c_fail 的量纲 | 四阶段任务，建议是单件任务的 4~5 倍。若单件约 300 步，取 1200~1500 步 |
| 成功判据 | 精确到公差和稳定帧数 | 四个工具中心与槽位中心水平偏差 < X mm、姿态偏差 < Y°、连续稳定 ≥ 15 帧 |
| 附加记录 | 每集完成件数 0~4、随机种子、初始位姿 | 必须记，后面所有分析都靠它 |
| 数据格式 | rollout 与专家数据必须**逐项同 schema** | 同一套记录器录制。字段名、dtype、shape 有一项不一致，后面合并数据集就会失败 |

**过关标准**：拿同一个记录器录 5 条专家 + 5 条随机策略轨迹，能被同一份数据加载代码无差别读出来，
且成功判据在这 10 条上给出的结果和你肉眼看视频一致。

**这一步的特殊考虑（重要）**：你的任务是 **4 阶段串联**的。二值成功标签在这种任务上非常稀疏——
一个刚 SFT 出来的策略很可能 100 条里 0 条完整成功。三个应对方案：

| 方案 | 做法 | 什么时候用 |
|---|---|---|
| **A. 照常二值** | 就用"四个都到位"作为 success | **第一轮先这样**。即使整体 0 成功，n-step advantage 仍然能在"第 2 件插进去的那一瞬间"给出正信号——因为价值函数从专家数据里学到了"插进去=进展" |
| **B. 分级回报** | 把 `c_fail` 按未完成件数缩放（完成 3 件的失败集惩罚 = 完成 0 件的 1/4） | rollout 完成件数分布很分散（0~3 都有）时收益最大。需要改价值目标的几行代码 |
| **C. 拆子任务** | 每放一件算一集，四个子任务各自跑 RECAP，最后再拼 | 方案 A 的 rollout 几乎全是"第一件就失败"时。这最接近 π\*0.6 原论文对长程任务的处理 |

**推荐路线**：第一轮跑 A，同时记录完成件数。看件数直方图：
如果 ≥1 件的比例超过 30%，继续 A/B；如果 90% 都卡在第一件，直接转 C。

---

### Step 1：基线策略 π₀（如果还没有）

**做什么**：用专家数据做标准 SFT，得到第一个能动的策略。RECAP 是**迭代改进**方法，
必须有一个起点策略去 rollout。

**输入**：清洗过的专家示教数据（建议 ≥200 集，四阶段任务最好 500+）。
**输出**：checkpoint π₀。
**过关标准**：π₀ 在你的评估协议下成功率 > 0（哪怕只有 2%）。**完全为 0 也能继续**——
rollout 全是失败数据依然对价值函数有用（提供负样本），只是收敛会慢，
而且要靠专家数据独撑正样本那一侧。

---

### Step 2：Rollout 采集

**做什么**：让 π₀ 在随机初始条件下反复做任务，把每一次的完整轨迹录下来。

**关键决策**：

1. **采多少集**：建议 150~200 集。经验上 rollout 与专家的比例在 **1:1 到 1:1.5** 之间比较稳
   （我们用的是 200 专家 : 150 rollout）。太少则失败模式覆盖不足，太多会淹没专家的正样本。

2. **随机化范围要"可解"**：这是个容易忽略的坑。如果初始摆放里存在**物理上不可能成功**的情形
   （比如工具正好压在工具箱边沿上、两个工具重叠），这些集会产生"无论怎么做都失败"的轨迹，
   价值函数会把那些视觉特征误学成"这种画面=必败"。
   **做法：采集用的随机化范围要比评估协议略保守**（排除掉几何上无解的摆放），
   但**评估必须严格用官方/原定的协议**，否则数字没有可比性。
   具体到你的任务：算一下工具最长边旋转后的外接半径，保证任意两个工具的初始位置间距、
   以及工具到工具箱的距离都大于这个半径 + 余量。

3. **记录内容**：除了标准的观测/动作，一定要存 **随机种子**和**初始位姿**，
   否则失败集无法复现、无法定位是策略问题还是场景问题。

4. **并行与算力**：单条轨迹的耗时 = 单集时长 / 实时率。参考：一集约 1 分钟，
   两个进程并行录 150 集约 2 小时。如果多个任务抢一张卡，推理会慢 10 倍
   （我们实测 1.7s/次 → 17s/次），**开跑前先确认显卡空闲**。

**输出**：150 条轨迹 + 每条的种子与元信息。
**过关标准**：数据集能被加载校验通过（集数对得上、每集帧数 > 0、视频文件完整）；
成功率落在预期区间（新策略 0~10% 都正常）。

---

### Step 3：打成败标签

**做什么**：给 150 条 rollout 每条打上 success/failure，写进边车文件。

**具体流程**：

1. 脚本按 Step 0 定的判据自动判一遍，产出初标；
2. **人工复核所有被判成功的**（数量少，通常 10 条以内，几分钟的事）——重点看
   判定触发之后工具有没有滑出、有没有把别的工具带出来；
3. 抽查 10~20 条被判失败的，确认没有假阴性（比如工具其实到位了，只是姿态角超了 1°）；
4. 有异议的直接改边车文件，**人工标签优先级高于脚本**。

**输出**：`episode_success.json`，每条含 `episode_index / success / n_placed / seed`。

**过关标准**：人工复核后的成功率与你对策略能力的预期一致。
**看一眼完成件数直方图**，这决定 Step 0 里 A/B/C 方案的取舍。

**常见翻车**：脚本"稳定 N 帧"计数达标就提前结束这一集 → 后续掉出来的情况看不到。
这是我们真实踩到的：150 集里有 1 集被这样误判成功。

---

### Step 4：构建数据池

**做什么**：把专家数据和 rollout 数据合并成一个数据集，并把成败标签写成每一集的属性。

**要点**：

- 池子里**必须同时有成功和失败**。理想比例：正样本（专家 + 成功 rollout）占 50~60%。
  你的任务初期成功 rollout 极少，正样本几乎全靠专家撑，所以专家数量不能太少。
- **专家数据必须是清洗过的版本**。RECAP 会把专家整体标成 success，
  如果里面混着"人操作失误但没删掉"的脏轨迹，价值函数会学到"这种失败画面也是成功"，
  直接污染最关键的正样本锚点。我们的经验：1000 集原始数据清洗后剩 756 集，必须用后者。
- 合并后**固定顺序为 `[专家…, rollout…]`**，这样 rollout 的全局索引 = 专家集数 + 局部索引，
  排查问题时能一眼对上。
- 转换/合并工具会丢掉非标准文件，**转换后记得把边车文件复制回去**。

**输出**：一个合并数据集，每集带 `episode_success` 字段。
**过关标准**：随机抽 5 集，其 `episode_success` 与边车文件一致；总集数 = 专家数 + rollout 数。

### Step 5：训练价值函数

**做什么**：在数据池上训 §2.2 的模型。

**参考配置**：batch 64、lr 5e-5、warmup 500 步、cosine 衰减、201 bins、全量微调。
显存约 27.5GB，约 5.4 秒/步。

**训多久**：**这是最反直觉的一点——不要训满。**
经验：350 集的数据池，1 epoch ≈ 2500 步；训到 3000 步（约 1.2 epoch）效果最好，
训到 6500 步反而废掉（见 Step 6）。计划 3000~4000 步、每 500 步存一个 checkpoint 即可，
而不是照着"loss 还在降"一直训。

**参考 loss 曲线**（用来判断有没有训崩，不是用来选 checkpoint 的）：

```
step:      0     500    2000   3000   5000   6000+
loss:     5.3 →  2.0  →  1.4  →  1.2  →  0.83 →  0.72（平台）
```

**工程注意**：这是数小时的长任务，**必须让它脱离你的终端会话**
（`setsid nohup ... < /dev/null & disown`），否则关掉 ssh / 重启 IDE 就全没了。
我们真的因为这个在 step 440 丢过 50 分钟——差 60 步就到第一个存档点。

**输出**：一系列 checkpoint（000500 / 001000 / … / 003000 / …）。
**过关标准**：loss 单调下降到 1.5 以下且没有 NaN。**注意：loss 低不代表能用，见下一步。**

---

### Step 6：★ 质检选 checkpoint ★（整条链路最关键的一步）

**为什么必须做这步**：小数据池（几百集）上，一个 0.7B 的模型会**记住每一条轨迹的回报**。
一旦记住了，按 Bellman 恒等式 `A_t = Σr + V(t+n) − V(t)` 就会**恒等于 0**——
价值函数看起来"很准"（loss 极低），但 advantage 全是 0，二值化出来的标签是纯噪声，
后面的 ACP 微调等于白做，而且你在最后评估之前完全看不出来。

**怎么做**：取一个小的评估子集（比如 60 集：10 条成功 rollout + 30 条失败 rollout + 20 条专家），
在**多个 checkpoint** 上分别做推理，比较三个指标：

| 指标 | 含义 | 想要的方向 |
|---|---|---|
| **分离度** = 成功集首帧均值 V − 失败集首帧均值 V | 价值函数能不能区分"这条会成/会败" | **≥ 0.3**，越大越好 |
| **advantage 标准差** | advantage 还有没有信号 | **越大越好**，塌到 0 就是记忆化了 |
| **近零帧占比**（\|A\| < 0.01 的比例） | 记忆化程度 | 越低越好，超过 90% 就废了 |

**选档规则**：**在分离度 ≥ 0.3 的 checkpoint 里，选 advantage 标准差最大的那个。**

真实数据（试管入架任务）：

| checkpoint | 分离度 | A 的标准差 | 近零占比 | 判断 |
|---|---|---|---|---|
| 1500 步 | 0.11 | — | — | 欠训练，价值函数还分不清成败 |
| **3000 步** | **0.43** | **0.030** | **70%** | **✓ 选它** |
| 6500 步 | 0.69 | 0.005 | 96% | 分离度更高，但 advantage 塌了 5~6 倍——记忆化，弃用 |

注意 6500 步这一档：**分离度是最好的、loss 是最低的，但它是废的**。
只看 loss 或只看分离度都会选错。

**效率提示**：一定要用子集（60 集约 10 分钟/档），别在全量 16 万帧上做（每档 2 小时）；
并且**在数据集副本上做**，不要把质检产生的中间列写进正式数据集。

**输出**：一个被选中的 checkpoint 编号。
**过关标准**：至少有一个 checkpoint 同时满足分离度 ≥ 0.3 且近零占比 < 90%。
**都不满足怎么办**：说明数据池本身有问题——通常是正样本太少（加专家数据）
或标签有污染（回 Step 3 复核）。

---

### Step 7：全量推理，把 advantage 写回数据

**做什么**：用选中的 checkpoint 在**整个数据池**上推理，给每一帧写三列：

| 列名 | 含义 | 用途 |
|---|---|---|
| `value` | V(s)，[-1, 0] | 分析、可视化 |
| `advantage` | n-step advantage | 二值化的中间量 |
| `acp_indicator` | 0/1，任务内 top-30% | **训练时真正被用到的那一列** |

按 §2.3 的公式：先从 V\* 差分出稠密奖励，再算 50 步 advantage，最后在任务内取 70% 分位数二值化。

**输出**：带三列标注的数据集。建议**同时产出两个版本**：

1. **reward 版**：带三列，用于 ACP 微调；
2. **no-reward 版**：完全相同的数据但不带三列，用于训**对照组**。

**对照组不是可选项**。ACP 版和对照版必须是"同数据、同步数、只差 prompt 里那个标签"，
否则最后成功率提升了，你无法回答"到底是 advantage 起作用，还是单纯因为多了 150 集 rollout 数据"。

**过关标准**：
- 三列都实际存在于文件里（转换工具丢列是常见事故，要显式检查）；
- 全局 positive 比例 ≈ 30%（这是分位数直接保证的）；
- 分开统计：专家帧 positive 比例约 10%、rollout 帧比例更高，是**正常**的（原因见 §2.3）；
- 抽几条成功 rollout 画 `value` 随时间的曲线，应该整体上升、并在每次成功插入时有台阶。
  **这张图是最直观的健康检查**，四个工具应该看到四级台阶。

---

### Step 8：ACP 微调

**做什么**：用 reward 版数据集微调 VLA，训练时按 §2.3 把标签拼进 prompt。

**要点**：

- 拼接格式固定为在原指令后追加一行 `Advantage: positive` / `Advantage: negative`；
- dropout 0.3；
- **推理路径不需要任何改动**：请求里没有 indicator 字段，代码自动追加 positive。
  这是 ACP 的最大工程优点——部署侧零改动；
- 归一化统计量（norm stats）要按**新数据集**重算。常见坑：训练框架只检查
  "这个配置名的统计目录存不存在"，第二轮换了数据集但配置名没变 → 静默复用旧统计量 →
  归一化错误但不报错。**显式确认统计量是按当前数据集 id 生成的**；
- **同时训对照组**：同样步数，用 no-reward 版数据，或者把标签开关关掉。

**输出**：ACP 策略 π₁ + 对照策略 π₁-SFT。

---

### Step 9：评估

**做什么**：在**原定的评估协议**（不是 Step 2 那个保守的采集协议）下，跑足够多的集数对比。

| 对比项 | 说明 |
|---|---|
| π₀（基线） | 起点 |
| π₁-SFT（对照） | 专家 + rollout 数据的纯 SFT。**这是真正的对照基线** |
| π₁-ACP | RECAP 产物 |

**建议指标**（不要只看成功率，尤其是四阶段任务）：

1. **完整成功率**（四件全到位）——最终指标，但初期可能都很低、区分度不够；
2. **平均完成件数**（0~4）——**初期最有信息量的指标**，能看出"从平均 0.8 件到 1.6 件"这种真实进步；
3. **首件成功率 / 逐件条件成功率**——定位卡在哪一阶段；
4. **平均完成用时**——价值函数目标里含"剩余步数"，ACP 通常还会让动作更果断、更快。

**集数**：100 集起步。成功率 5% 左右时，100 集的统计误差约 ±2%，
所以**不要为 1~2 个百分点的差异下结论**，看不出差别就加到 200~300 集。

**评估时的坑**：对照组模型评估时**必须确认没有偷偷追加 `Advantage: positive`**——
它没在这个条件下训练过，多这一句会让 prompt 与训练分布不一致，结果偏低，
你会得到一个虚高的"提升"。

---

### Step 10：进入下一轮

- 用 π₁ 重新做 Step 2 的 rollout（成功率应该更高了，正样本变多）；
- Step 4 的数据池 = 专家 + 第一轮 rollout + 第二轮 rollout（**池子是累积的**）；
- 价值函数**重新训**（数据分布变了，不要复用上一轮的价值模型）；
- 三列标注加轮次后缀（`value_round2` 等），不要覆盖上一轮的列；
- 上一轮的数据当输入复用时，**务必确认边车标签还在**，否则失败集会被整体标成 success。

一般 2~3 轮能看到明显收益，之后收益递减，取决于任务上限和数据规模。

## 第 7 章 十个真实踩过的坑

1. **价值函数训过头**（最重要）。loss 持续下降 ≠ 更好；记忆化后 advantage 按 Bellman 恒等式塌向 0。
   永远做多档质检。
2. **标签在格式转换中丢失**。边车文件是唯一可靠载体，每次转换后显式复制回去；
   上一轮数据复用时若边车缺失，失败集会被整体标成 success——训练直接废，且不报错。
3. **专家数据没清洗**。RECAP 把专家整体标 success，脏轨迹会污染正样本锚点。
4. **采集场景里有物理无解的初始摆放**。采集用保守随机化，评估用原协议。
5. **rollout 与专家的 schema 不一致**。字段名/dtype/shape 差一项，合并就失败；用同一套记录器。
6. **长任务被会话重启杀掉**。`setsid nohup … < /dev/null & disown`，
   验证父进程是 1。我们丢过 50 分钟，差 60 步没到存档点。
7. **杀进程时把自己杀了**。`pkill -f "xxx"` 会匹配到执行这条命令的 shell 本身
   （它的命令行含同样字符串）。用 `pgrep -f 'xx[x]'` 的括号技巧，或先把 PID 写文件再按号杀。
8. **孤儿子进程占着显存不放**。杀掉主进程后，负责写图像/视频的子进程可能存活，
   `nvidia-smi` 显示 20+GB 被占但进程列表里找不到父进程。用
   `nvidia-smi --query-compute-apps=pid` 逐个清理。
9. **归一化统计量跨轮不重算**。框架只看配置名目录存不存在 → 第二轮静默复用旧统计量。
10. **对照组评估时错误地挂了 positive 标签**。它没在这个条件下训过，
    会得到虚高的"提升"。对照组必须显式关掉标签拼接。

## 第 8 章 名词表

| 术语 | 解释 |
|---|---|
| **VLA** | 视觉-语言-动作模型。输入图像+状态+指令，输出动作块 |
| **episode / 集** | 一次完整的任务尝试，从复位到结束的一整条轨迹 |
| **rollout** | 让策略自己去跑任务并录下轨迹（相对于人类遥操作的"示教"） |
| **SFT / 行为克隆** | 用示教数据做监督学习，让模型模仿人的动作 |
| **专家数据** | 人类遥操作采集的高质量示教数据 |
| **价值函数 V(s)** | 给状态打分：从这里出发预期能拿到多少回报（这里 = 能不能成 + 还要多久） |
| **advantage A** | 优势。"实际走出来的结果" 减去 "价值函数原本的预期"，>0 表示这段做得比预期好 |
| **n-step** | 往后看 n 步再用 V 兜底（bootstrap）来估回报，n 越大越接近真实回报但方差越大 |
| **bootstrap** | 用模型自己的估计值来代替"后面还没看到的那部分回报" |
| **c_fail** | 失败惩罚常数，让失败轨迹的价值明显低于成功轨迹 |
| **分布式价值头** | 把标量值域切成若干 bin 做分类，比直接回归稳定 |
| **two-hot** | 目标值落在两个 bin 之间时，按距离分配到相邻两个 bin 上 |
| **ACP** | Advantage-Conditioned Policy，把 advantage 作为条件（这里是一句 prompt 文本）喂给策略 |
| **dropout（标签）** | 训练时以一定概率不加标签，让模型也保留无标签下的能力 |
| **norm stats** | 归一化统计量。对每个数据集统计动作/状态的分布，训练和推理必须用同一份 |
| **checkpoint** | 训练过程中保存的模型快照 |

1. 专家数据 200 集 + π₀ rollout 150 集，二值成功标签（方案 A），额外记完成件数；
2. 价值函数训 3000 步，每 500 步存档；
3. 质检 1500/2000/2500/3000 四档，按"分离度 ≥ 0.3 里选 A 标准差最大"选一档；
4. 写回三列，出 reward / no-reward 两版；
5. ACP 微调 + 对照组，同步数；
6. 评估 100 集，主看**平均完成件数**。

跑通一遍之后再考虑方案 B/C、加轮次、扩数据。**不要一上来就四阶段全量 + 多轮迭代**——
中间任何一步的标签污染都会在两天后才暴露出来。
